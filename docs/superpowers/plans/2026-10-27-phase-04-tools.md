# Phase 04 — Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the grounded triage model four git-backed tools and a hand-written tool-use loop, serve it as `POST /triage/agent`, measure it on 40 val rows against retrieval and grounded, then compare the SDK's tool runner and show the trace in the UI.

**Architecture:** A new `agent/` package. `tools.py` wraps `git` at the pinned SHA behind a sandbox, `loop.py` is the hand-written loop ending on `GroundedTriageResult` via `output_config`, `explain.py` prints a run's message array, and `runner.py` is the SDK-runner comparison. The API, eval and UI consume `agent.loop.run`.

**Tech Stack:** Python 3.12, `anthropic==1.9.0` (`claude-haiku-5-5`), FastAPI, psycopg, pytest 9.1.1, git, React + TS (`useState` only).

**Spec:** `docs/superpowers/specs/2026-10-27-phase-04-tools-design.md`

## Global Constraints

- Anthropic only for the tool loop; `PROVIDER != "anthropic"` → 400 at the route.
- Tools read git at the SHA in `data/pinned_sha.txt` (`M.PINNED_SHA`), never the working tree. For Vite: `99bd9d1d46153fa939f4a304cc0177db42e28776`.
- Caps: `read_file` ≤ **400** lines per call; `grep` ≤ **50** matches; any tool output ≤ **20,000** chars; `ToolCall.output` preview ≤ **2,000** chars; `git_log` `n` clamped to 1..**30**.
- `AGENT_MAX_TURNS` env, default **12**, counts API calls.
- Model mistakes become strings starting `Error: `, sent back as `is_error: true`. Tools never raise for bad model input.
- Message history is append-only: assistant turns are `response.content` whole.
- `suspected_files` from the agent must exist at the pin and pass `M.is_gold_candidate`. `/triage/grounded` keeps its candidates-only rule.
- No paid API call inside `pytest`. Paid runs: eval 40 rows (~$0.60), explain 1 run, runner 3 runs.
- `MEASUREMENTS.md` is append-only. Commits carry no attribution trailer. Never commit private-repo data.

## Review Focus

1. **Tool used on the wrong kind of path** (`read_file` on a directory, `list_dir` on a file): expect an `Error:` string naming the mistake, not a crash. Tests in Task 2.
2. **Invalid regex** (`grep("(")`): expect an `Error:` string. Test in Task 2.
3. **Inverted or out-of-range line range** (`end_line < start_line`, `start_line` past the end): expect an `Error:` string stating the file's length. Test in Task 2.
4. **Parallel tool calls** (two `tool_use` blocks in one response): expect both run, in order, both results in a single user message. Test in Task 3.
5. **`end_turn` whose text isn't valid JSON**, or a response with no text block: expect `RunError` carrying the partial run, not an unhandled exception. Test in Task 3.
